# 服务专项条款

**生效日期：2026 年 8 月 10 日**

本《服务专项条款》是《[用户协议](/legal/terms)》的补充，说明具体功能和集成的运作方式。若本文件与《用户协议》就同一事项发生冲突，以本文件为准；其余事项继续适用《用户协议》。

## A. Vendor 条款透传

Kiro.bus 将每次取 API key 请求路由到独立的上游 Vendor。请求路由到 Vendor 时：

- **您同时接受该 Vendor 的条款** —— 该 Vendor 的服务条款、可接受使用政策、内容政策、商业许可、及任何地区限制均适用于您对该 key 的使用；
- **Vendor 的变更会自动传导** —— 可用性、价格、配额、模型版本、输出策略、生命周期事件按 Vendor 自己的节奏变化。我方没有提前通知，也无法预阻；
- **我方不为 Vendor 的行为负责。** 若 Vendor 拦截您的请求、下线模型、调价或终止对我方的接入，我方在可能范围内绕行；底层决定不是我方能做或推翻的。

## B. 上游模型厂商条款透传

Vendor 又路由到模型厂商（Anthropic、OpenAI、Google、AWS Bedrock、Azure、Vertex 等）。这些厂商的政策通过 Vendor 透传给您：

- 只要您的 key 路由到相应厂商，Anthropic Usage Policy、OpenAI Usage Policies、Google 模型政策、AWS Acceptable Use Policy 及其等价政策都对您适用；
- 若模型厂商明确禁止某种用例，即使 Vendor 自己的条款未提及，您也不得通过该路由使用该用例；
- 我方不保证任何 Vendor 在任何模型厂商侧的账号状态；这属于 Vendor 与模型厂商之间的事。

## C. 协议与兼容性

Kiro.bus 的网关不绑定协议。您从 Kiro.bus 取到的 key 是 Vendor 签发的标准 API key。之后的协议兼容性属于 Vendor 和模型厂商，不属于我方：

- key 可与上游支持的任何工具与协议（OpenAI 兼容、Anthropic Messages、Claude Code、Codex、Bedrock、Vertex 等）配合使用。我方不额外保证协议覆盖范围或 SDK 行为；
- 我方在商业合理范围内保持自身路由和 webhook payload 的稳定和向后兼容；确需调整时，会在 changelog 公告，并在可能情况下留兼容窗口。

## D. 拼车（bus）机制

- **一辆车对应一个 Vendor 账号。** 同车的所有车友共享同一个上游 Vendor 账号。这既是拼车便宜的原因，也意味着并发、RPM、TPM、配额是共享的。这是 Vendor 账号本身的属性，不是我方调度的 bug；
- **费用分摊。** 默认按人头分摊每一轮的费用。不均摊规则（按用量分、有人推自己的 key 进车等）在车详情页说明；
- **推自己 key 抵扣。** 如果您把自己的 key 推入某辆车，其他车友使用该 key 时按 1:1 返积分到您的钱包。每轮结束时结算；
- **余额不足挂起。** 本轮所需积分不足时，系统不给您推 key，车照常跑但这一轮跳过您。连续 3 轮不足 → 挂起，不再参与拼车分摊，直到您补上钱包积分；
- **中途下车。** 当前这一轮的积分不退 —— API key 已经取出来了。从下一轮开始不再收费也不再推新 key。已经拿到的 key 归您。

## E. 质保与补车

- **质保窗口。** 每一把 API key 附带质保窗口，我方在此期间监控存活。窗口内失效，系统自动补一把新的，并按比例退回已扣积分；
- **补车触发 webhook。** 每一次补车、退款、状态变更都推 webhook（payload 见 [/docs](/docs)）。下游自动化应以这些事件为准；
- **质保不覆盖的情况。** 质保仅覆盖探针可观测的失效信号（鉴权失败、硬拦截、配额响应）。**不覆盖** Vendor 政策变更、模型下线、输出质量下降、主观性能问题，或 Vendor 侧的账号级状态。

## F. 明文提取（handoff）

- **单次交付。** 选择明文提取后，我方仅交付一次并立即删除本地副本；
- **提取后不再质保。** API key 到您手上后，我方无法监控、补车或退款。需要质保和补车请把 API key 留在自己的 API key 池或车里；
- **账本保留。** 我方在您的账本中保留脱敏的 handoff 记录（vendor、时间戳、消耗积分）用于售后与审计；明文本身不留存。留存详情见《用户协议》§J。

## G. 推入您自己的 API key 池

- 可以把 Kiro.bus 指向您自己的 API key 池（在设置里配 URL + token）。我方为您取的每把 key 都会同时写入您的池并在 Kiro.bus 侧继续监控；
- **双写。** key 同时存在于两处。它失效时我方仍然补车、仍然退款；
- 您的 API key 池是您的基础设施，我方不为其可用性、安全或数据负责。

## H. API key、webhook 与自动化

- **API key。** 您可以在控制台创建 `usr-` 前缀的 API key。每把 key 继承您账号的速率限制、配额和策略。用 API key 发出的请求归属于您的账号；
- **Webhook 签名。** 所有向外的 webhook 都用您的 webhook 密钥签名。服务端应校验签名；未签名或签名无效的投递应丢弃；
- **投递重试。** 失败的投递按指数退避在有限次数内重试。当前重试计划见 [/docs](/docs)；
- **速率限制。** 每个端点的速率限制在文档公开。持续超限会触发限速，进一步会临时暂停违规的 API key。
