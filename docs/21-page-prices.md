## 1. 为什么推翻 v1（折线图）

v1 想把「一天」压成**一个值**画曲线，试了三种画法**全都不对**：

| 画法 | 问题 |
|---|---|
| 均价曲线 | 看不到当天最高 / 最低 —— 用户要知道"实际能买到的最好价" |
| 阶梯 `stepAfter` | 一天里出现两个值，逻辑矛盾 |
| 平滑曲线 `monotone` | 暗示价格连续变化，不符实；且造出数据里没有的圆弧 |

**根因**：数据是**三层**的 —— `vendor → 每天 → 每轮`。上游一天发多轮车，每轮单价按整车产出量查阶梯表（产量大→单价低）。**一根曲线表达不了三层**。

v1 还有个致命缺陷：**看不出 vendor 的发车情况**（一天几轮、活跃不活跃），而这是判断"这家值不值得依赖"的核心信息。

## 2. 数据模型（轮次级）

**存轮次，不存每日聚合** —— 聚合值前端派生，信息不丢。

```ts
VendorRound {
  time: ISOTime;        // 发车时刻
  zone: Zone | null;    // null = 该 vendor 不分区
  unit_price: Money;    // 这轮单价（已含附加费）
  keys_count: number;   // 这轮产出多少个号
}

VendorDayRounds {
  date: string;
  rounds: VendorRound[];   // 空数组 = 那天没发车
}

VendorPriceTrend {
  vendor_id / vendor_label / zone
  days: VendorDayRounds[]
  // 以下都从 days 派生 · 后端算好下发省前端遍历
  current_price / price_high / price_low / price_avg
  total_rounds / avg_rounds_per_day
  change_30d_pct / no_service_days / longest_streak_days / in_stock_now
}
```

**关键**：`price_high` / `price_low` 取的是**轮次单价**的极值，不是"每日均价"的极值 —— 用户想知道实际能买到的最好 / 最差价。

## 3. 图表：箱线矩阵（Box Plot Small Multiples）

```
                          7/10        7/16        7/22        7/28
Vendor 04 [最便宜][车最稳]  ▏  ▎  ─  ▎  ▏  ·  ▎  ▏  ▎  ─  ▏  ▎     +5%
均 29  27-31 · 日均 1.9 轮

Vendor 03 [车最多]          ▎ ▏▎▏▎ ▏▎▏ · ▎▏▎▏▎▏▎              +45%
均 37  23-49 · 日均 6.3 轮 · 2 天没车
```

**每根竖条 = 某家某天的全部轮次**，同时表达 4 个维度：

| 视觉 | 含义 |
|---|---|
| 竖条上下端 | 当天**最高 / 最低轮次单价** ← 用户要的极值在这 |
| 竖条颜色深浅 | 那天几轮车（行内相对量 · 车多则深） |
| 短横线 | 那天只发 1 轮（没有区间） |
| 灰点 | 那天没发车 |

### 3.1 为什么不用别的图

| 方案 | 否决理由 |
|---|---|
| 蜡烛图 / OHLC | 只能画一家 · 6 家叠不了；且我方没有"开盘价 / 收盘价"语义 |
| 区间带 + 均线（单图 6 家） | 6 条带子重叠糊成一片 |
| 散点图（每轮一点） | 最忠实但太吵（30 天 × 6 家 × 日均 4 轮 ≈ 720 点） |

**箱线矩阵**是唯一同时满足「6 家横向对比」+「看到每天极值」+「看出发车密度」的。

### 3.2 Y 轴每行独立（不共享）

各家价格量级差太多（Vendor 04 是 26-33，Vendor 05 是 48-66）。共享 Y 轴会把每行的竖条压成一条几乎无高度的线，完全看不出当天价差。

**代价**：不能靠"竖条高低位置"横向比价。
**补偿**：左列直接给数字（均价 + 区间），比目测更准。

### 3.3 颜色：统一品牌紫（深浅表达轮数）

v1 给 6 家配 6 个色相，是为了区分**重叠**的折线。现在每家独占一行，**不存在重叠** → 不需要区分色相。

统一 `#9147FF`，深浅表达"那天几轮车"，符合 `13-frontend-research.md`「vendor 用同色系、不用杂色」。

## 4. 信息分层（图看趋势 · 列表看记录）

**页面两段** —— 明细不塞 tooltip，下沉到列表：

```
┌ 箱线矩阵 ─────────────────┐   ← 看趋势：谁贵谁便宜、谁车多、谁断供
│ 6 家 × 30 天 · 竖条 = 当天价格范围 │
└──────────────────────────┘
          ↓ 点某根竖条筛选
┌ 发车记录 ─────────────────┐   ← 看记录：每一轮的时刻/区/单价/产出
│ 时间 · vendor · 区域 · 单价 · 产出 · 当天位置 │
└──────────────────────────┘
```

### 4.1 图表交互

- **hover 某行** → 该行高亮、其他行淡到 30%
- **hover 某根竖条** → 竖虚线指示 + tooltip **只给当天概要**（发车 N 轮 / 区间 / 均价 + 「点一下看明细」）
- **点某根竖条** → 下方列表筛到「该 vendor + 该天」· 竖条加外圈标记选中 · 再点一次取消

### 4.2 发车记录列表

**每条 = 一轮车**（这才是最细粒度的记录）：

| 列 | 内容 |
|---|---|
| 时间 | `08/08 22:40`（日期 + 发车时刻） |
| vendor | 按 §8.20 身份显示 |
| 区域 | us / eu / 全区 |
| 单价 | 当天最低标绿 · 最高标红 |
| 产出 | N 个号 ← 配合单价能看出阶梯规律 |
| 当天位置 | `当天最低` / `当天最高` Chip · 或 `N 轮中` / `唯一一轮` |

- **默认**：全部 vendor 混流按时间倒序（看最近发车动态）· 692 轮
- **筛选后**：只看那家那天 · 副标显示「Vendor 03 · 07/26 · 6 轮」+ 「清除筛选」按钮
- **分页**：`LoadMoreButton` 每次 +20 条
- **点列表行**也能筛（跟点图等效）

**为什么不把明细放 tooltip**：tooltip 塞 7-9 行明细会很高、遮住图、且没法滚动/复制/分页。列表是明细的正确容器。

## 5. 左列信息（每行）

```
AWS-Q Kiro Vendor 03  [车最多]
均 37   23-49  ·  日均 6.3 轮  ·  2 天没车
```

- vendor 名（按 `§8.20` 身份显示真名 or 匿名编号）
- 标记 Chip（可并存 · 走统一 `Chip` 组件不自造 badge）：
  | 标记 | 条件 | tone |
  |---|---|---|
  | 最便宜 | 区间均价全网最低 | brand |
  | 车最稳 | 0 天没车 | ok |
  | 车最多 | 日均轮数全网最高 | neutral |
- 均价（加粗）+ 区间 + **日均轮数** + 没车天数

**日均轮数是 v1 缺失的关键指标** —— 判断这家活跃不活跃、值不值得依赖。

## 6. Mock 数据生成规则

**禁止**：随机噪声、正弦叠加造走势 —— 那是编造数据（`decisions §8.22` 已记）。

```
1. 基准价慢速漂移 · 3-8 天调一次（振幅大的调得勤）
2. 每天发 N 轮 · roundsB 基线 ±1，再按几何分布追加（偶尔爆发多轮）
3. 每轮产出量 5-40 个号 · 单价 = dayBase × 阶梯因子
   阶梯因子：产量 5 → +intra · 产量 40 → −intra（产量越大越便宜）
4. 发车时刻 08:00-23:00
5. noService 概率 → 那天 rounds = []
```

每 vendor 的 `range / noService / roundsB` 不同，所以形态各异：
- `kiroappio` 最稳：日均 1.9 轮、0 天没车、价差窄（27-31）
- `kirooo` 最活跃：日均 6.3 轮、价差宽（23-49）、偶尔没车

**种子**：`mulberry32(fnv1a("vendorId:zone"))` —— 同 vendor 的 us / eu 数据独立，且每次刷新结果一致。
